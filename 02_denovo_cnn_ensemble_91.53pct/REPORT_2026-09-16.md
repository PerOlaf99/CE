## Longest error-free read (SNP not counted) — new golden-bar metric

Added as a second acceptance bar (GOLDEN_STANDARD.md): **longest consecutive
run of matching columns on the SAME best-HSP**, computed from blastn's gapped
`qseq`/`sseq` columns, with the known template mutation column (M13 fwd 5977;
called T vs the RC-of-G C) treated as **neutral** — it neither counts nor breaks
the run, so a clean read crossing the mutation site is not penalized.

96-well plate means (A01 DLL example: run 506, fwd 5719→6226; without SNP
exclusion the raw run would be split to 257):

| caller | longest error-free run (mean) | median | min | max | wells > 500 |
|---|---|---|---|---|---|
| DLL | **398.1** | 375.5 | 228 | 626 | 33 |
| track_bases | 286.5 | 280.5 | 114 | 590 | 5 |
| trackB+add-only | 213.6 | 210.0 | 93 | 335 | 0 |

Interpretation: the two bars are complementary — `matched_bp` rewards total
real bases recovered (track_bases wins via the longer real tail); `longest_run`
rewards a CLEAN read (DLL wins: fewer scattered errors, ~96.8% identity).  The
tail that wins matched_bp is exactly where track_bases' errors concentrate
(~8.4% error rate in the tail third), so its clean stretch is shorter.
**The eventual acceptance target is a caller that beats the DLL on BOTH bars at
once.**

## The CNN / DSP divide (why fusion is asymmetric)

- The CNN ensemble (`v4_{clean,pos,pos_b}`) was trained on peaks produced by
  the greedy engine.  On those it is strong; `refine_denovo_v2`'s drop phase
  is essential (tuned this week: jitter=1, add_p=0.65, gap_frac=1.35,
  stutter_p=0.65, drop hi/lo 0.55/0.40 -> +0.32 over default on pbM13).
- But on DSP positions the same CNN reads low confidence: `refine`'s drop
  removes exactly the tail track_bases recovered, and re-labeling destroys
  more.  Hence the ONLY safe use on top of track_bases is the add-only
  (gap-insertion) stage with drop disabled.
- Practical shipping advice: ship `tuned_calls/` (track_bases).  The add-only
  variant is a +0.07% optional upgrade.

## Mutation internal standard (verified, corrected coordinates)

Reference search + BLAST mapping pinned the coordinates (the earlier note only
said "5977"):

- **M13 forward pos 5977 (1-based) = G** (flank `CCGTCTC[G]CTGGTGA`).
- Read-wildtype motif `CACCAGCGAGACGGG` starts at **M13 fwd 5983**; the
  sequencing read carries **T** there (`CACCAG[T]GAGACGGG`), a **C→T**
  transition on the read strand (G→A on the forward/reference strand).
- A01 ESD read-strand base at **ESD index 308 (0-based) = T**.
- Both shipped callers preserve the T in **96/96** wells.  The add-only
  refine occasionally inserts a few spurious homopolymer bases next to the
  motif in some wells, but the T residue itself is always called.
